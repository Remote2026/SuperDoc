# doc-chat 功能与方案(2026-11-18)

上传 .docx → SuperDoc SDK 解析章节结构 → Mastra Agent 分步分析 → 结果流式显示在 CopilotKit 聊天窗。本文档记录当前功能边界、技术方案,以及以 SuperDoc Agent SDK(`createAgentToolkit`)为首的未来开发计划。

---

## 一、当前功能

| 功能 | 状态 | 说明 |
|---|---|---|
| 上传 .docx | ✅ | 仅收 .docx、≤50MB;落盘 `uploads/<uuid>.docx`,返回 docId |
| 上传后预处理 | ✅ | `preprocess.ts`:先 `doc.blocks.list`(完整文本)→ 标题栈算法层级归类,持久化 `uploads/<docId>.hierarchy.json`;预处理失败不影响上传(fixture 对比数据在 `fixtures/out/`) |
| 章节结构分析 | ✅ | Agent 分 3 步:① 调工具提取骨架 → ② 检查层级跳级/编号跳号/空章节 → ③ 输出 markdown 报告(目录树+问题清单+总评) |
| 流式聊天窗 | ✅ | CopilotKit Vue `CopilotChat`,SSE 实时显示工具调用进度与模型输出;分析后可自由追问 |
| 自动分析 | ✅ | 上传成功即自动触发分析,无需手动发消息 |
| "最近文档"语义 | ✅ | 工具 docId 可选,缺省自动取最近一次上传(单用户本地场景) |
| LLM 供应商切换 | ✅ | DeepSeek(默认)↔ vLLM 只改 `.env` 三行(OpenAI 兼容协议) |
| 三种运行形态 | ✅ | A 开发双进程 / B 单进程同源托管 / C Electron 桌面壳 |
| 质量门禁 | ✅ | `npm run verify` = 双端类型检查 + 18 个测试(含真实调用 SuperDoc 二进制抽取、上传端到端) |
| 文档写回/编辑 | ❌ | 本期刻意只读(见未来计划 #1) |
| 全文内容问答 | ⚠️ 有限 | 追问基于"章节骨架",不含正文段落内容 |

## 二、技术方案

### 2.1 架构与调用链

```
Vue3 前端 (web/)                    Node 服务端 (server/)                    外部
┌──────────────────┐   SSE    ┌─────────────────────────────────────┐   ┌──────────┐
│ App.vue          │◄────────►│ index.ts 装配                        │   │          │
│  └ CopilotChat   │ /api/    │  └ app.ts                            │   │          │
│ UploadPanel.vue  │ copilotkit│     ├ POST /api/upload → registry    │   │          │
│  └ POST /api/    │          │     └ copilotHandler ──┐             │   │          │
│    upload        │          │  CopilotRuntime v2 ◄───┘             │   │          │
│  useAgent/Context│          │   └ MastraAgent(@ag-ui/mastra)       │   │          │
└──────────────────┘          │      └ Agent doc_analyzer (mastra.ts)│   │          │
                              │         └ tool extractDocumentStructure│  │          │
                              │            = tools.ts                │   │          │
                              │            → superdoc.ts             ├──►│ SuperDoc │
                              │              open()+extract()→骨架JSON│   │ CLI 二进制│
                              │         └ model: openai-compatible ──┼──►│ DeepSeek │
                              │            (baseUrl/model 走 .env)    │   │ /vLLM    │
                              └─────────────────────────────────────┘   └──────────┘
```

### 2.2 分层职责

| 层 | 文件 | 职责 |
|---|---|---|
| UI | `web/src/App.vue`、`UploadPanel.vue` | 布局、上传、自动触发分析、agent 上下文发布 |
| 传输 | CopilotKit runtime v2(`index.ts` 接线) | SSE 事件流、agent 发现(`/api/copilotkit/info`)、线程(open 模式) |
| 编排 | Mastra `Agent`(`mastra.ts`) | LLM 多轮循环、分步 instructions、工具调度 |
| 工具 | `tools.ts` | 把 SDK 能力包成模型可调用工具(描述/schema/execute) |
| 解析 | `superdoc.ts`、`registry.ts` | SDK 单例懒连接;extract 骨架折叠 + blocks.list 块级查询;docId→路径登记 |
| 预处理 | `preprocess.ts` | 上传后 blocks 全量拉取(含正文)→ 标题栈层级归类(Group 树,保序保 nodeId) |

### 2.3 关键设计决策

1. **SuperDoc SDK 必须在 Node 侧**:SDK spawn 平台原生二进制(linux-arm64 等),不能进浏览器 bundle → 解析、工具执行、API key 全在服务端。
2. **docId 不经模型传参**:`useAgentContext` 的 context 经 MastraAgent 转发到工具 `requestContext`、不进 prompt → 工具缺省取 `registry.latest()`,对单用户最稳。
3. **骨架裁剪**:原始 `extract()` 全量 blocks 太大,折叠为 `{标题, 层级, 每节段落数}` 供模型分析,省 token 且聚焦结构。
4. **接线选型**:用 `MastraAgent + CopilotRuntime(v2) + createCopilotExpressHandler`,未用要求跑完整 Mastra server 的 `registerCopilotKit`。
5. **client 进程级单例、懒连接**:遵循 SDK README(一档一开/关,退出时 dispose),避免每次调用付宿主启动开销。

### 2.4 运行形态

| 形态 | 命令 | 说明 |
|---|---|---|
| A 开发 | `npm run dev:server` + `npm run dev:web` | Vite :5173 代理 /api → :8787,双端热更新 |
| B 单进程 | `npm run build && npm start` | server 同源托管 `web/dist`,:8787 |
| C Electron | `npm run build && npm run electron` | 主进程 spawn 内嵌 server(`ELECTRON_RUN_AS_NODE`),uploads 进 userData |

## 三、未来开发计划

### 1.(核心)接入 SuperDoc Agent SDK `createAgentToolkit` —— 让 agent 获得"写"能力

**背景**:当前工具面是只读的。SuperDoc 官方在 `@superdoc/sdk` 同包提供 `createAgentToolkit`,交付"工具定义 + 系统提示词 + dispatch 函数"三件套,核心是两个工具:`superdoc_inspect`(只读文档快照)与 `superdoc_perform_action`(编辑动作入口:文本替换、批注/回复/解决批注、tracked changes、表格与样式操作等),配套安全保存流程(`doc.save({ out })` 另存,不覆盖源文件;零变更/失败即拒绝保存)。

**与现有架构的关系**:不是替换,是补位——Mastra 继续负责模型循环与 UI 桥接,`createAgentToolkit` 作为文档执行层挂进 `tools.ts`(官方支持 `openai/anthropic/vercel/generic` wire shape,Mastra 走 Vercel AI SDK 格式或 generic 适配)。

**分期**:

| 期 | 内容 | 验收 |
|---|---|---|
| P1 | 包装 `superdoc_perform_action` 的批注类 action(add_comments / comment_paragraphs / resolve_comments) | chat 里说"给第 2 章加一条批注" → 生成带批注副本,原文件不变 |
| P2 | 文本替换 + tracked changes 类 action(replace_text 等) | "把全文 X 替换成 Y 并以修订呈现" → 另存修订版 docx |
| P3 | 表格/样式操作(insert_table_row、apply_style…) | 结构编辑指令可完成 |
| P4 | 结果分发:保存路径回显/下载入口(Electron 内目录定位) | 分析+修改闭环 |

**风险与约束**:dispatch 隐藏接受的 `superdoc_execute_code` 等名称严禁暴露给模型(官方警告);编辑循环需带 MAX_TURNS 与失败回执校验;每步先加测试(TDD 延续)。

### 2. 全文内容问答

骨架之外补正文层:按需把章节段落分块喂给模型(或本地检索),使"第 2 章讲了什么"不依赖模型猜测。与 #1 的 inspect 快照可共用底层读取。

### 3. vLLM 私有化落地

协议层已就绪(`@ai-sdk/openai-compatible`),待用真实 vLLM 端点验证工具调用与流式兼容性,固化到部署文档。

### 4. 多文档管理

突破"最近上传"单文档语义:文档列表、切换指定 docId、跨文档对比分析;registry 已具备 id→路径基础。

### 5. Electron 打包分发(linux-arm64)

`electron-builder --linux AppImage deb` 实跑与签名/图标/自动更新评估;产物已配置 extraResources 携带各平台 SuperDoc 原生二进制。
